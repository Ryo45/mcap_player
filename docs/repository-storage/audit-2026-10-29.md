## 隔離mirrorでの実測

Git LFS 3.4.1、全ref対象。元の作業リポジトリ・リモートは変更していない。

| 条件 | fresh mirrorのsize-pack | LFS全履歴payload |
| --- | ---: | ---: |
| GitHubから取得した現状 | 145.79 MiB | 0 |
| 推奨：上記150パスだけLFS | 87.03 MiB | 81,959,657 bytes / 144 objects |
| 比較：埋め込み画像も含む197パス | 27.70 MiB | 137,768,535 bytes / 184 objects |

推奨案はfresh Git object storeで約40.3%削減（約58.76 MiB）。画像まで移す案は約81%削減するが、記事閲覧の図がLFS依存になるので推奨しない。
これはfresh cloneの保存packを使った比較であり、ネットワークのHTTP転送byteを直接測ったものではない。packのまとめ方・clone時期によって多少変わる。
LFSを全部取得する人には別途約78.16 MiBのpayloadが必要で、Git+LFS総量や所有者の保存課金を必ず減らす案ではない。

同じblobが保護対象にも存在すればGitから消えない。パス容量だけをclone削減量と誤認しないこと。
先端でLFS化するcommitだけを追加しても、過去のblobが到達可能なままでこの削減は得られない。**既存cloneの転送削減には履歴書き換えが必要**。

## 検証

- 新規一時mirrorで `git lfs migrate import --everything --skip-fetch`。本番remoteなし、uploadなし。
- 141のmapped commitすべてを照合。候補以外のblob IDとパスが不変、既存attributesを保持、144のpayload versionのSHA-256・サイズ・LFS cacheの内容を検証。fresh cloneで `git fsck --full` 成功。
- 本番の全refは実験前後で一致。
- `.lfsconfig` を加えた一時repoから、skip-smudge環境変数なし・実際のLFS filter有効で通常clone：取得payload 0。
- 単一ファイルをローカルfile:// LFS remoteから明示取得：取得payload 1。preflightは取得前に失敗と取得方法を表示、取得後成功。GitHub LFSへのupload・download試験ではない。
- 候補150パスがpointerのままの一時cloneで `docker/check.sh` 完走。tool単体テスト5件、policy check、Rust fmt、workspace clippy/test、実fixtureのNative bindingsテスト、WASM check、Trunk release build、ROS 2 Liveテストが成功。ROS Liveは95 passed / 5 ignored。
- 既存の基本ビルド・デモ・テストにLFS payloadが不要なことを確認。全ての過去の手動分析スクリプトを実行したわけではない。
